Measurement-Driven Diagnosis and Mitigation of Host-CPU Co-location Interference in Single-GPU LLM Serving on a Multi-GPU Server

7 学校预印本 2026-05-26 · Guanjie Cheng; Guowei Li; Yingying Wen; Xinkui Zhao; Zhe Liu; Shuiguang Deng / arXiv
方向:云端serving方向:调度服务硬件:CPU硬件:GPU
这是什么GPU 服务器的宿主 CPU 在大模型推理时常常闲着，想混部别的 CPU 任务又会伤服务质量，这篇论文测清楚了伤在哪里。
有什么结果主要实验中，不加保护地混部 nginx 会让吞吐下降 78.8%、首 token 时延上升 429.5%、逐 token 时延上升 362.4%；按该方法指导加保护后，nginx 吞吐最高提升 4.4 倍、逐 token 时延降低 4.5 倍；在统一基线的服务等级目标下，12 个可行的留出用例全部满足，而两个对照策略分别只满足 10 个和 11 个，同时把实时调度的使用从 28 例降到 22 例，平均同租户降速从 56.65% 降到 51.21%。
怎么做到研究发现主要问题不是 GPU 算子变慢，而是 CPU 侧的服务阶段在提交 GPU 任务之前出现长尾被放大；为此提出两个度量指标刻画这一效应，并据此搭建一套测量驱动的诊断流程，依次做负载风险筛查、服务阶段长尾剖析、操作系统级保护策略选择和解码服务等级目标的合规验证。
评分依据：面向多卡服务器上的推理服务混部问题，与端侧设备无关，仅「CPU 侧阶段才是长尾来源」这一诊断视角有一般性参考，相关度低。贡献在于用实测把干扰来源从 GPU 算子纠正到 CPU 服务阶段。
