microsoft/onnxruntime: [CUDA] Add session-scoped MoE/QMoE offload planner, lifecycle controller, and memory budget ledger (#33451)

10 开源大项目 开源 2026-10-31 · microsoft / GitHub
方向:MoE方向:推理框架方向:量化硬件:GPU硬件:CPU
这是什么ONNX Runtime 为 CUDA 后端加入会话级的 MoE/QMoE 专家卸载：显存装不下的大型混合专家模型，可以把热门专家留在 GPU、冷门专家放到 CPU 内存甚至直接从权重文件按需读取。
有什么结果未报告；配套文档说明目标场景是把 45–63 GiB 专家权重的 MoE 模型跑在 24–32 GiB 显存的消费级或工作站 GPU 上，同一个模型包无需改图即可在大显存服务器卡和小显存机器之间切换。
怎么做到会话初始化时用五阶段规划器按显存和锁页内存预算决定每层留在 GPU 的专家数，可读取离线专家热度表做非均匀分配；冷专家用 CPU 的 AVX-512/AVX2 小核计算并与 GPU 计算在同一个 CUDA Graph 里重叠，新变热的专家后台异步提升，权重文件以只读共享方式映射以控制内存占用。
评分依据：让本地 PC 和工作站在显存不足时也能跑大型 MoE 模型，对本地部署有直接参考价值，但实现只针对 CUDA GPU、没有手机或 NPU 场景；专家冷热分层加 CPU/GPU 重叠执行是成熟思路，本次贡献在于做成了通用运行时能力，且尚无实测数字。
