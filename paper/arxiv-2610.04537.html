PhaseGate: Phase-Aware CPU Retrieval Scheduling for On-Device LLMs on Unified Memory

15 学校预印本 开源 2026-10-03 · Seoyoon Yum; Sehoon Kim / NeurIPS 2026 Workshop
方向:调度服务方向:高效推理应用:RAG硬件:Apple-Silicon硬件:GPU硬件:CPU模型:Qwen
这是什么在 Mac 这类 CPU 和 GPU 共用内存的设备上，本地助手一边用 GPU 跑大模型、一边用 CPU 做向量检索，检索会抢内存带宽、拖慢出字速度。PhaseGate 根据大模型当前处于预填充还是解码阶段，动态决定放行多少个检索任务。
有什么结果在 M4 设备上，4 个并发 HNSW 检索让解码阶段 p95 每 token 时延上升 60–61%，首 token 时延只上升 5.7–6.9%。PhaseGate 在 base-M4 Mac mini 上选出“预填充放 4 个、解码放 1 个”的配额，检索吞吐 1.6 kQPS，是满足时延约束的最佳固定配额（0.78 kQPS）的 2.0 倍，7 次留出测试中两项 p95 时延都控制在无检索基线的 1.25 倍以内；只按时间表切换、不看阶段的对照组吞吐相近，但 7 次全部超出出字时延上限。M2、M2 Pro Mac mini 上结论一致（吞吐为固定配额的 1.8 倍、2.5 倍）。
怎么做到先离线标定：在给定时延预算下，分别为预填充和解码阶段挑出能稳定达标的最大检索并发数；运行时由 MLX-LM 推理框架上报阶段切换，检索队列只在当前阶段的上限内放行新任务，已在执行的检索不抢占。
评分依据：直接面向端侧助手在 Apple Silicon 统一内存上的真实资源争用，用 4-bit Qwen2.5-1.5B 加 FAISS 检索在 M4、M2、M2 Pro 多台 Mac 上实测，相关度 9。调度策略本身简单，但“解码对内存争用远比预填充敏感、按阶段放行检索”这一发现清晰、可直接落地，贡献 6。论文被 NeurIPS 2026 端侧智能研讨会接收（非主会）；实验中检索与生成相互独立、采用合成负载，没有构成完整的 Agent 闭环。
