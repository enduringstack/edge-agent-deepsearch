Can Agent Harnesses and Inference Engines Hear Each Other? The HEAR Protocol for Agentic LLM Serving

9 学校预印本 2026-10-05 · Jiaqi Zhao; Haodong Chen; Jitai Hao; Wei Zhao; Jinghao Pang; Qiang Huang; Jun Yu / arXiv
方向:云端serving方向:KV cache方向:调度服务模型:Qwen
这是什么智能体工作流的编排层（harness）知道任务依赖和上下文生命周期，推理引擎知道请求队列和 KV cache 状态，但两边之间没有标准接口互通信息。HEAR 定义了一个双向协议，让编排层把工作流意图告诉引擎、引擎把运行时状态回传编排层。
有什么结果在内存受限、并发服务的设置下，SCBench 上批处理速度提升 1.61 倍，首 token 中位时延降低 2.23 倍（P95 降低 1.45 倍）；BrowseComp-Plus 上端到端从 5.69 小时降到 4.62 小时（1.23 倍）且准确率不降（46.63% 对 46.15%）；DeepResearchBench 上端到端提速 2.45 倍。
怎么做到协议只规定双方交换什么语义（工作流意图、执行需求、引擎状态、能力和结果），具体优化策略可插拔；论文实现了两种策略：按缓存命中情况在线调度请求，以及按智能体角色选择不同的执行模式（如不同的 KV 压缩方式）。
评分依据：面向智能体工作流的推理服务协调，实验在单张工作站 GPU 上用 vLLM 服务 Qwen3-8B，属于云端/服务端场景，端侧相关度 3；把编排层和引擎之间的信息交换标准化是有价值的系统抽象，贡献 6。作者来自哈尔滨工业大学（深圳）。
