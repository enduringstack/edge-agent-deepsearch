Run Deterministic SQL Before Asking a Local LLM to Plan

9 官方动态 开源 2026-10-09 · Microsoft / Microsoft
Microsoft方向:工具调用方向:规划推理方向:安全隐私应用:RAG硬件:CPU
这是什么系列文章第 7 篇：在医院本地服务器上做病历问答时，计数、分组、趋势这类精确问题不应交给语义检索，也不该每次都让本地大模型写 SQL，而是先用确定性解析生成 SQL，解析不了时才调用本地 LLM 规划。
有什么结果正文没有量化结果；作者明确说明新的 QuerySpec 中间表示只是已确定的目标设计，目前实际运行的代码仍是基于表名的 SQL 模板匹配。
怎么做到先用一套按顺序匹配的语法规则把问题解析成不含物理表名的 QuerySpec，再通过各数据源的 schema 绑定落到具体表和列，最后按数据库方言编译成 SQL；解析失败时让 Foundry Local 上的本地模型以工具调用方式填写同一个 QuerySpec，最多修复一次；所有 SQL 都要经过语法树策略、表白名单、行数上限、代价预检和只读超时执行。
评分依据：面向只有集成显卡或 CPU 的本地服务器，把稀缺的本地推理算力只留给长尾问题，对资源受限设备上的 LLM 规划和工具调用有直接借鉴。设计思路清晰，但尚未实现，也没有实验数据。
