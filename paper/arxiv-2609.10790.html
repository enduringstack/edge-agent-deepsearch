Composable CXL Memory as a Kubernetes-Native Shared Memory for LLM Serving

7 学校预印本 2026-09-09 · Hongjian Fan; Kevin Zhang; David Habinsky; Sean Dykstra / arXiv
方向:KV cache方向:云端serving方向:调度服务
这是什么把可组合的 CXL 内存做成 Kubernetes 能调度的资源，让跨节点的容器共享同一块物理内存来复用 KV 缓存。
有什么结果在两节点集群配 512 GiB CXL 设备上跑 Qwen2.5-7B-Instruct，跨节点前缀复用在外部命中率 95.4% 到 99.5% 时把首 token 时延降低 5.5 到 36.6 倍，而节点本地的显存前缀缓存和 CPU 内存卸载只能回退到完全重算；跨节点与同节点复用的时延比只差 1% 到 4%。
怎么做到用 Kubernetes 动态资源分配驱动按需组合 CXL 区域，在各主机上呈现为 DAX 设备并以同一个容器设备接口名注入容器；给 vLLM/llm-d 的共享内存连接器把该区域当作 KV 缓存层，槽目录直接嵌在共享介质里，省掉外部元数据服务。
评分依据：是集群级内存解耦，与端侧场景关系很远，仅在缓存复用思路上相通（相关性 2）。是可行性研究，作者也这样定位（贡献 5）。
