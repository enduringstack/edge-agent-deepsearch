PatchKV: Efficient KV Cache Recovery for Dynamically Edited LLM Contexts

11 学校预印本 2026-08-18 · Guotao Yang; Rui Guo; Siwei He; Sheng Chen; Yitao Hu; Keqiu Li / arXiv
方向:KV cache方向:云端serving方向:量化应用:长上下文推理模型:Qwen模型:Llama
这是什么长时间运行的大模型智能体经常改写上下文中间的一段（比如更新工具结果或计划），后面很长的文字没变，但缓存的 KV 已经因为位置和前文变化而失效。PatchKV 让这种“改中间、留后缀”的场景能快速恢复 KV 缓存，而不必整段重算。
有什么结果在 8 卡 A800 服务器上用 Qwen3-32B、GLM-4-9B、Llama-3.3-70B 和三种长上下文问答负载测试：恢复后的首 token 时延比整段后缀重算快 2.51–3.85 倍，比 CacheBlend 快 1.26–2.06 倍；9 个设置中有 6 个 F1 持平或更好，其余差距不超过 1.36 分。8k token 检查点在 CPU 内存中占 799.4 MiB，介于 INT8（1023.4 MiB）和 INT4（523.4 MiB）之间。
怎么做到把前后两版上下文拆成不变前缀、被改片段和对齐后缀；用离线拟合的漂移模型预测改动附近需要重算的“脏区”，再依据存储的注意力挑出少量远处关键块一起重算；其余后缀块按预先标好的精度从 CPU 内存取回，在一条融合路径里完成反量化、RoPE 位置校正和 KV 页放置。
评分依据：面向服务器端智能体负载的 KV 缓存复用，实验在 A800 数据中心 GPU 上完成，但混合精度 KV 恢复和选择性重算的思路可迁移到内存紧张的端侧长上下文场景，端侧相关度 5。针对“中间编辑”这一常被忽视的缓存失效场景给出系统化方案，贡献 6。
