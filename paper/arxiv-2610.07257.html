MemMux: Runtime Verification and Honest Resource Attribution for Fleets of Parallel Coding Agents

13 学校预印本 开源 2026-10-05 · Sumanyu Muku / arXiv
方向:调度服务应用:代码硬件:Apple-Silicon
这是什么开发者越来越常在一台电脑上同时跑十几个编码智能体，每个都会拉起语言服务器、测试进程和浏览器，很容易把内存吃满导致 OOM 或疯狂换页，丢掉没提交的修改。MemMux 是一个本机运行时，专门管住这些智能体进程树的内存，并把管理效果变成可随时检查的信号。
有什么结果在 15.3 GiB 内存的 Linux 主机上、每个智能体占 1.4 GiB 的过载场景中，MemMux 把整个智能体集群控制在 7.5 GiB 预算内且零换页，而 tmux 等不做管控的工具把机器顶到内存上限、约 2 GiB 被挤进交换区；结束智能体时 MemMux 回收 100% 子进程，裸进程基线会遗留一半（10 个孤儿进程、303 MiB），注入的 10 个逃逸子进程它全部发现。每秒一次的归属扫描在 1 个智能体时占约 0.6% CPU，10 个时 2.7%。在 Apple M4 Max 上用真实 Claude Code 会话验证，归属准确率 100%。
怎么做到常驻守护进程每秒扫描一次本机进程树，把每个进程归到所属智能体；按内存预算决定放行哪些智能体、压力大时主动回收，结束时清理整棵子树并报告逃逸进程；同时用统一基准把它和 tmux、专用智能体多路复用器、裸进程启动方式放在相同负载下对比。
评分依据：编码智能体的工具调用与执行（终端、语言服务器、测试、浏览器）实际跑在开发者本机，MemMux 管的正是这层本机执行闭环，并在 M4 Max 笔记本上用真实 Claude Code 验证，按 PC 端智能体计，相关度 8；不过主体实验在云主机上用合成负载完成，方法是进程级资源治理的工程整合，贡献 5。唯一作者署名 Amira Learning。
