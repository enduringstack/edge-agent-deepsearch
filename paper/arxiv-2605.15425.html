Runtime-Structured Task Decomposition for Agentic Coding Systems

7 公司项目 2026-05-14 · Shubhi Asthana; Bing Zhang; Chad DeLuca; Hima Patel; Ruchi Mahindru / arXiv
IBM; Zoom方向:规划推理应用:代码
这是什么用大模型做代码调试、故障根因分析的 Agent 常把整套流程塞进一个大提示词里，一处失败就得整条重跑。这篇提出把任务拆分和执行流程交给可执行的控制代码来管，只让大模型做局部判断。
有什么结果在 Kubernetes 根因分析任务上，重试开销从单体方案的 904 token、静态拆分的 1632 token 降到 436 token；多文件调试任务从 703/933 token 降到 460 token。整体比单体方案重试成本最多低 51.7%，比静态拆分低 73.2%。
怎么做到由程序控制子任务划分和分支，模型输出先按预定义 schema 校验再进入下游，失败时只重跑出错的子任务而不是整条流程。
评分依据：属于云端编码 Agent 的运行时编排，与端侧部署无直接关系，但“只重跑失败子任务”的做法可迁移到资源受限的 Agent 运行时。方法偏工程整合，实验规模较小（每种配置 10 次运行）。PDF 首页作者 1、3、4、5 署名 IBM Research，作者 2 署名 Zoom（注明工作完成于 IBM Research 期间）。 作者机构依据：arXiv PDF 首页署名 IBM, Zoom（PDF 首页作者 Shubhi Asthana、Chad DeLuca、Hima Patel、Ruchi Mahindru 署名 IBM Research（ibm.com 邮箱），Bing Zhang 署名 Zoom（zoom.com 邮箱））。
