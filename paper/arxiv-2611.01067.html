Ripple: Deadline-Aware CPU-GPU Sharing for Embodied Inference

15 学校预印本 2026-10-31 · Jiadong Zhang; Xiaosong Ma / arXiv
方向:调度服务方向:高效推理硬件:GPU硬件:DGX应用:机器人模型:Qwen
这是什么机器人等边缘设备用统一内存芯片同时跑大模型推理和避障、建图等实时 CPU 任务时，GPU 吃满内存带宽会让实时任务超时。Ripple 是一个 CPU-GPU 协同调度器，专门解决这种“推理抢带宽”的问题。
有什么结果在 DGX Spark 上用 4 组机器人 CPU 任务搭配 Qwen3-8B/32B 和 Qwen3-VL 推理测试，Ripple 是唯一在所有截止期设置下都满足 2% CPU 超时率目标和 VLM 截止期、同时保住 LLM 尽力吞吐的方案。
怎么做到把推理拆成可暂停的逐层单元，按模型推算每层要搬多少 GPU 内存字节；再把每个 CPU 任务剩余的截止期余量折算成“GPU 字节预算”，只放行不超预算的推理，并按实测完成情况在线调整、必要时收窄 GPU SM 占用。
评分依据：在 DGX Spark 这类统一内存边缘设备上真机实现并评测，直接面向机器人端上 LLM/VLM 与实时控制共存（相关度 8）；在没有带宽计数器的情况下用截止期余量换算 GPU 字节预算，思路新颖（贡献 7）。作者来自 MBZUAI；属调度系统而非 Agent 闭环，判为非端侧Agent。
