Beyond Fluent Generation: A CPU Reliability Benchmark for MCP-Style Tool Calling in Sub-2B Small Language Models for Edge Deployment

14 学校预印本 2026-09-07 · Abrar Shahriar Qurat-Ul-Ain Mastoi / arXiv
方向:工具调用方向:评测基准方向:高效推理硬件:CPU模型:Qwen模型:Phi
这是什么面向树莓派、Jetson Nano 这类单板计算机上的小模型 agent，专门测它们按 MCP 方式调用工具时到底靠不靠谱：能不能吐出机器可读的 JSON、选对工具、把参数填全。
有什么结果论文报告：Qwen2.5-1.5B 贪心解码 75%、采样 79%；Qwen2.5-0.5B 贪心 72% 但采样掉到 32%；Phi-1.5 为 0%，Pythia 和 TinyLlama 最高只有 7%。严格复核发现 1000 条原始回复里只有 5 条能直接当 JSON 解析，说明几乎完全依赖输出修复。资源探测显示 Qwen2.5-1.5B 需要 7960 MiB（摘要在此处被截断）。
怎么做到在 100 条覆盖天气查询、网页搜索、计算、写邮件和建任务的提示上评测五个 20 亿参数以下的开放权重模型，分贪心解码和核采样两档；用一个恢复式解析器剥掉 Markdown 围栏、抽出花括号片段，再分别给可解析性、工具名正确性、参数完整性和取值一致性打分。
评分依据：直接回答「端侧小模型现在能不能当工具调用 agent 用」，还给了 CPU 内存占用，对单板设备选型很有参考；评测本身方法常规，但「1000 条里只有 5 条原生可解析」这个结论足够有冲击力。
