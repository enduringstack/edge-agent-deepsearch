AstronOS: A Unified Execution Model and Runtime for Long-Horizon Agentic Systems

8 公司项目 2026-08-17 · Zhenhang Nie; Gui Zheng; Xudong Sun; Tailong Zhu; Bin Zhang / arXiv
iFLYTEK方向:记忆方向:规划推理模型:GPT
这是什么长任务往往要跨多次模型调用和多个会话才能完成，但现有 Agent 系统常把状态绑在单次对话上，换一个新会话就丢了前面定好的计划。科大讯飞提出一套执行模型，让一项工作在多次调用之间保持身份和带版本的权威状态，并在自家 AstronOS 运行时里实现。
有什么结果10 个受控任务、每种策略重复 3 次共 150 次执行：在三阶段任务上 AstronOS 15 次中通过 14 次，重读原始材料为 0/15、回放完整历史为 2/15，文本摘要和 JSON 交接均为 0/15；按通过次数折算的模型 token 成本更低，但每次尝试耗时更长；单阶段任务上各策略表现接近。
怎么做到每一步只拿到某个状态版本加上本步新到的材料作为输入，结果先校验、记录成功后才推进为新版本状态；Case、Task、Scenario Pack 三类对象分别承载工作项、执行单元和流程定义，任务可以在中心编排和本地桌面连接器之间分派。
评分依据：这是 Agent 运行时的状态管理工作，实验用的是云端模型，本地桌面连接器只是产品路径、基准测试里并未实际使用，与端侧部署关系较远（相关度 3）。把“跨会话交接计划”做成带版本的状态推进，思路清楚但评测规模较小（贡献 5）。作者机构依据：PDF 首页 5 位作者均署名 iFLYTEK Co., Ltd.（合肥），通讯邮箱为 iflytek.com。 作者机构依据：arXiv PDF 首页署名 iFLYTEK（PDF 首页 5 位作者均署名 iFLYTEK Co., Ltd.（合肥），通讯作者邮箱为 iflytek.com）。
