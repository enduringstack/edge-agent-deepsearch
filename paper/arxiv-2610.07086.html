SchemaFill: Efficient LLM Tool Calling via Slot-Parallel Speculative Decoding

13 学校预印本 开源 2026-10-05 · Zhi-Kai Chen; Song-Yan Li; De-Chuan Zhan; Han-Jia Ye / arXiv
方向:投机解码方向:工具调用模型:Qwen
这是什么智能体调用工具时要逐个 token 生成 JSON 格式的工具名和参数，调用多、字段多时延迟很高。SchemaFill 利用工具定义里明确的参数结构，提前并行猜测后面多个参数槽的值，再交给目标模型一次性验证，在输出不变的前提下加速工具调用生成。
有什么结果用 Qwen2.5-7B-Instruct 在单张 RTX PRO 6000、批大小为 1 的设置下，Glaive 和 BFCL 上端到端吞吐分别比逐 token 自回归快 3.73 倍和 4.05 倍，比 EAGLE-3 快 1.51 倍和 1.87 倍，比 ToolSpec 快 1.75 倍和 1.56 倍；在 Qwen3-8B、Mistral-7B 和基于 Llama-3.1-8B 的 Hermes-3 上也做了验证。
怎么做到按工具定义预测会出现哪些工具调用和参数槽（用 BM25 给候选工具排序），为后面的多个槽位并行起草候选值，把跨字段、跨调用的候选拼起来，在真实输出前缀下由目标模型统一验证；只提交验证通过的 token，不一致时由目标模型给出更正。
评分依据：工具调用是端侧智能体的主要时延来源之一，批大小为 1 的加速方法可直接迁移到端侧，但实验在工作站 GPU 上完成，端侧相关度 6；利用工具参数结构做跨槽位并行投机解码，思路新颖，贡献 7。作者来自南京大学，代码已开源。
