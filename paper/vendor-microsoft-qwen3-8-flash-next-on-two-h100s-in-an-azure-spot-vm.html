Qwen3.8-Flash-Next on two H100s in an Azure Spot VM

6 官方动态 开源 2026-10-12 · Microsoft / Microsoft
Microsoft方向:云端serving方向:MoE方向:高效注意力方向:KV cache方向:投机解码硬件:H100模型:Qwen
这是什么Azure 博客实测：用 vLLM 在一台双 H100 的 Spot 虚拟机上部署 Qwen3.8-Flash-Next（总参数 125B、每 token 激活 6B 的 MoE，主体为线性注意力），并在编码智能体的真实负载下做全链路观测。
有什么结果15 万 token 上下文下单请求约 200 token/s、首 token 不到 1 秒（95% 提示命中前缀缓存），5 路并发稳定，到 7 路时每 20 个请求有 1 个首 token 等待 23 秒以上；关闭思考时单请求 260 token/s（27B 稠密版为 166）；基础评测 44/45，Terminal-Bench 2.0 的 10 个短任务完成 8 个；Spot 价格每小时 3.22 美元，比按量付费便宜约 80%。
怎么做到FP8 权重按张量并行切到两张卡，KV cache 也用 FP8 存储以腾出缓存容量，同时开启前缀缓存和 MTP 投机解码；用 OpenTelemetry 把 vLLM、网关和 GPU 计数器接入 Application Insights 与 Grafana，并修正了投机解码下每请求速度等指标的误读。
评分依据：这是云端 GPU 上的大模型部署与观测实践，与端侧无关，只有 KV cache 精度、投机解码和缓存命中方面的经验可参考。属于工程部署经验总结。
