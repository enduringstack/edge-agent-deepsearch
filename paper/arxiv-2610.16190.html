A New Lens on Multi-GPU Communication: API-Level Memory Models for Portable Optimization

6 公司项目 2026-10-12 · Johnathan Alsop; Bradford Beckmann; Brandon Potter; Jiakun Yan; Aurelien Bouteiller; Omri Mor; Tony Tye; Sameer Sahasrabuddhe / arXiv
AMD方向:云端serving方向:MoE硬件:GPU
这是什么多 GPU 通信越来越成为机器学习和高性能计算的瓶颈，但 rocSHMEM、NCCL 这类设备端通信库缺少严格的内存模型，激进优化容易出错。本文为设备端通信接口定义了 API 级内存模型，并在 AMD 的 rocSHMEM 中实现。
有什么结果在每节点 8 张 AMD Instinct MI300X 的环境中，按模型放宽排序约束后，集合通信负载最高提速 2.48 倍，计算与通信融合负载最高 1.77 倍，前沿的专家并行通信负载最高 1.18 倍。
怎么做到在 API 层定义通信原语的内存语义、屏蔽底层细节，再通过形式化的约束放宽让网络数据可以安全地绕过缓存，在保持标准接口的同时做底层性能优化。
评分依据：面向数据中心多 GPU 通信，与端侧无关，只与大模型推理基础设施有宽泛联系；把内存模型引入通信 API 层有一定系统贡献。作者署名为 AMD。 作者机构依据：arXiv PDF 首页署名 AMD（PDF 首页全部 8 位作者统一署名 AMD）。
