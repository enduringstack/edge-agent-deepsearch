Hardware Keystores for AI Agent Signing Workflows: A Zero-Trust MCP Enforcement Architecture

12 公司项目 开源 2026-08-06 · Leo Sambrook; Sampo Sovio / arXiv
Huawei方向:安全隐私方向:工具调用应用:安全
这是什么AI 智能体越来越多地替人签 Git 提交、签文档，私钥却常放在智能体能读到的文件或环境变量里。这篇把私钥放进 HSM/TPM 等硬件密钥库，并设计一套零信任防护栈，防止被注入的指令借智能体之手去调用硬件签名。
有什么结果在 AgentDojo 提示注入测试中（3 个模型、144 次），攻击成功率从基线 18.1% 降到 0%；对被攻陷 MCP 服务器的工具投毒（MCPTox）同样全部拦住；越权调用在 1 毫秒内被拒绝；方案已在嵌入式 TPM 2.0（Infineon SLB9670）上验证可直接替换。
怎么做到把签名能力封装成 MCP 工具，外面套五层防护：工具清单白名单、预先承诺内容的哈希比对、语义过滤、会话约束，以及没有预先承诺时一律升级给人确认；保证安全性不依赖语义过滤判断正确。
评分依据：智能体运行时的工具调用安全，私钥留在本机硬件里并在真实 TPM 芯片上测了时延，对在个人设备上跑的智能体有直接参考价值；创新点在于把硬件密钥库的“代理人混淆”问题讲清并给出分层解法。两位作者均署名华为赫尔辛基硬件系统安全实验室。 作者机构依据：arXiv PDF 首页署名 Huawei（PDF 首页两位作者均署名 Huawei Technologies, Hardware Systems Security Lab Helsinki）。
