## 1. 方法（每个历史周一样的流水线）

每周一个独立工作目录 `research_runs/backfill/<label>/`（`EDGE_RUN_DIR`），所有命令带该周最后一天作为 `--today` / `EDGE_TODAY`。

1. **脚本采集**（串行，arXiv 会限流）：
   `arxiv_curl_sweep.py --today END --no-catchup`（历史窗口 recent-updates 不可达时自动写探测证据豁免）、`collect_hf.py`、`collect_github_releases.py`、`refresh_trending.py`（历史窗口自动跳过只反映“当下”的热榜页，只取窗口内新建仓）、`collect_vendors.py`（只作发现层）。
2. **子 agent**（并行）：
   - 厂商官方动态 A/B 两组（24 家），用 `vendor-research-guide.md` 的“历史窗口”入口（WordPress REST、全量 RSS、Apple 内嵌 JSON、Samsung 月度归档等），写 `candidates-vendor.json` 与逐厂证据。
   - 社区雷达（历史入口：HN Algolia、Reddit arctic-shift、Bluesky since/until、GitHub Discussions、HF createdAt；X 用 snowflake 定时 + 回核；YouTube 超过约 6 周记 limited）。
3. **证明 + 组装 + 异常门**：`attest_candidates.py`、`build_run_week.py --today END`。
4. **整理**：按 `research_runs/curation/CURATION_SPEC.md` 分批派整理子 agent（每批 ~30 条），主 agent 复核端侧 Agent 判定、推荐、公司归属后合并。
5. **编辑**：主 agent 写本周判断（≥5 条外部要闻）、翻译 GitHub 线索描述。
6. **写存档**：`python agent/backfill_week.py write --label L --end END ...`（按本周窗口校验，自动剔除已在其他周出现的条目，生成详情页）。
7. **硬件雷达**按月做（第 3 阶段），完成后 `backfill_week.py set-hardware` 写回各周。
8. **构建与部署**：每完成 3–4 周就 build、过门、提交、把新周页/详情页覆盖部署到 gh-pages。

### 每周命令清单（`research_runs/backfill/` 下的工具，已入库）

```bash
export GITHUB_PERSONAL_ACCESS_TOKEN=...   # 只放环境变量；不带 token 时 GitHub API 每小时 60 次，release 覆盖会记成 unproven
bash research_runs/backfill/collect_week.sh L END            # 1. 脚本采集（串行，可后台链式跑多周）
python research_runs/backfill/gen_prompts.py L END           # 2. 渲染厂商 A/B、社区子 agent 任务说明 -> prompts/L/*.txt
#    子 agent 提示词只需一句：“先读取并严格执行 <prompts/L/xxx.txt>”
python research_runs/backfill/combine_vendors.py RUN_DIR END # 3. vendors_A/B.json -> candidates-vendor.json + manifest 厂商覆盖
EDGE_RUN_DIR=RUN_DIR python agent/attest_candidates.py --today END
EDGE_RUN_DIR=RUN_DIR python agent/build_run_week.py --today END --manifest RUN_DIR/collection-manifest.json
python research_runs/backfill/make_batches.py RUN_DIR RUN_DIR/run-*.json 34   # 4. 整理批次 -> RUN_DIR/batches/input_N.json
#    整理子 agent 写 batches/out_N.json；主 agent 把编辑判定写进 RUN_DIR/decisions.json
python agent/curation_merge.py --run RUN_DIR/run-*.json --curated RUN_DIR/batches/out_*.json --decisions RUN_DIR/decisions.json --out RUN_DIR/curated.json
python research_runs/backfill/set_trending_zh.py RUN_DIR RUN_DIR/trending_zh.json   # 5. GitHub 线索中文描述
python agent/backfill_week.py write --label L --end END --run RUN_DIR/curated.json --weekly RUN_DIR/weekly.json \
    --trending RUN_DIR/github_trending_top20.json --community RUN_DIR/community_radar.json   # 6. 写存档
```

编辑判定先例（保持各周一致）：云端模型的智能体、PC/手机只负责执行命令（如 Codex Windows 沙箱、模型位置不明的桌面 Agent）→ 非端侧Agent，可仍推荐；纯动作/控制策略（无规划/记忆/工具）→ 非端侧Agent；机载规则解析 + 语义记忆 + 导航闭环在设备上、仅疑难指令求助局域网 GPU → 其他端侧；智能体运行时与编排闭环（多设备互相委派、状态、授权、设备执行）在本地设备上、仅大模型推理调用云端（如 EdgeCitadel、HearthNet）→ 其他端侧；单机只执行云端智能体下发的工具命令（如 VIGIL）→ 非端侧Agent；撤稿论文 drop；Reddit 社区条目一律“仅线索”；同一工作的厂商博客与 arXiv 论文只留论文条目。

倒序回填的跨周归属：HF 每日精选按上榜日记日期，常比 arXiv 提交晚一周。`backfill_week.py write` 会把较晚一周里只以 HF 页面收录的论文“收回”到其 arXiv 提交所在周（与正向周更时 arXiv 扫描先收的结果一致）；较晚一周以 arxiv.org 收录的不动。
